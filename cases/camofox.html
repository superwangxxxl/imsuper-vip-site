CamoFox：给 AI Agent 用的隐蔽无头浏览器，快照比 HTML 小约 90%

基于 Camoufox 的 REST 浏览器服务：无障碍树快照、稳定元素引用、绕过常见机器人检测；适合给 Agent 当浏览后端。

CamoFox：给 AI Agent 用的隐蔽无头浏览器，快照比 HTML 小约 90% ​

你能得到什么：在自己机器上起一个浏览器 REST 服务，让 AI Agent 用「无障碍树快照 + 元素引用（e1、e2…）」操作网页，而不是把整页 HTML 塞进上下文；官方说明快照大约比原始 HTML 小 90%。底层是 Camoufox（在 C++ 层做指纹伪装的 Firefox 分支），比普通 Playwright / 无头 Chrome 更不容易被常见机器人检测拦住。适合：自己做 Agent、想让 Bot 稳定点网页/搜资料/过登录态的人。不适合：只想手动刷网页、或没有 Node.js / 装不动浏览器二进制的环境；也不要拿它去做违法抓取。

安装指南 ​

官方要求 Node.js ≥ 22（package.json 的 engines）。我们在 Linux 云电脑上用 Node 22.20.0 装通；本机若仍是 Node 20，会卡在依赖引擎检查。第一次 npm install 会下载 Camoufox 浏览器包（我们这次约 663 MB）和 GeoIP 库。

sh
git clone https://github.com/jo-inc/camofox-browser
cd camofox-browser
# 只要跑服务，可跳过开发依赖（其中含要求更高 Node 的 peer）
npm install --omit=dev
export CAMOFOX_CRASH_REPORT_ENABLED=false   # 可选：关掉匿名崩溃上报
export CAMOFOX_BIND_HOST=127.0.0.1          # 建议只绑本机
npm start
# -> http://127.0.0.1:9377
sh
npx @askjo/camofox-browser
sh
# 不要直接 docker build；用仓库自带的 make，会先拉二进制
make up

Linux 上若 better-sqlite3 编译失败，先装编译工具：sudo apt-get install -y build-essential。Debian/Ubuntu 常见。

装好后先确认服务活着：

sh
curl -s http://127.0.0.1:9377/health
# 期望大致：{"ok":true,"engine":"camoufox","browserConnected":true,...}

# 交互文档与 OpenAPI
# http://127.0.0.1:9377/docs
# http://127.0.0.1:9377/openapi.json

使用教程：开标签 → 拿快照 → 按 ref 点一下 ​

  1. 起服务：按上面装好后 npm start，端口默认 9377。
  2. 开一个标签（userId 和 sessionKey 都要带）：
  3. 拉无障碍树快照，里面的 [e1]、[e2] 就是可点的引用；再 POST /tabs/:id/click 带上 ref。
sh
# 1) 打开页面
curl -s -X POST http://127.0.0.1:9377/tabs \
  -H 'Content-Type: application/json' \
  -d '{"userId":"agent1","sessionKey":"demo","url":"https://example.com"}'
# -> {"tabId":"...","url":"https://example.com/","httpStatus":200,"navigationOk":true}

# 2) 拿快照（把 TAB_ID 换成上一步返回的 tabId）
curl -s "http://127.0.0.1:9377/tabs/TAB_ID/snapshot?userId=agent1"

# 3) 按 ref 点击
curl -s -X POST http://127.0.0.1:9377/tabs/TAB_ID/click \
  -H 'Content-Type: application/json' \
  -d '{"userId":"agent1","ref":"e1"}'

# 4) 用搜索宏（官方内置，例如 Google）
curl -s -X POST http://127.0.0.1:9377/tabs/TAB_ID/navigate \
  -H 'Content-Type: application/json' \
  -d '{"userId":"agent1","macro":"@google_search","query":"camoufox browser"}'

需要带登录态时：先 openssl rand -hex 32 生成密钥，启动前 export CAMOFOX_API_KEY=...，把 Netscape 格式 cookie 文件放到 ~/.camofox/cookies/，再走官方的 cookie 导入接口。没设 CAMOFOX_API_KEY 时，cookie 相关接口会直接 403（官方默认关闭）。

对外暴露时务必设 CAMOFOX_ACCESS_KEY，并继续把 CAMOFOX_BIND_HOST 限在可信网卡；生产环境不要裸奔在公网。

避坑与解决方案 ​

Node 版本不够 ​

engines 写的是 >=22。我们用 Node 20 试装时，peer 依赖 openclaw 还会要求更高版本的 Node，整次 npm install 失败。解决：升到 Node 22+；若只跑服务，可用 npm install --omit=dev 跳过开发依赖。

第一次安装体积大、耗时长 ​

postinstall 会拉 Camoufox 二进制（我们实测约 663 MB）和 GeoIP 数据库。网络差或磁盘紧时容易中断。解决：预留约 1 GB 空间；或按官方说明用 CAMOUFOX_EXECUTABLE=/path/to/camoufox-bin 指向已有安装包。

Cookie 导入一直 403 ​

没设 CAMOFOX_API_KEY 时，cookie 导入默认关闭。解决：启动前导出密钥环境变量；密钥不要写进会进 git 的配置文件。

原生内存持续涨 ​

仓库 Issues 里大量自动上报的 leak:native-memory（浏览器跑一会儿 native 内存涨几百 MB）以及偶发的 hang:navigate。解决：控制并发（MAX_SESSIONS / MAX_TABS_PER_SESSION）；闲置让它按 BROWSER_IDLE_TIMEOUT_MS（默认 5 分钟）收掉浏览器；长任务跑完 DELETE /sessions/:userId；盯 /health 里的 memory。

默认会装 uBlock，下载失败会拖垮启动 ​

官方环境变量 CAMOFOX_DISABLE_DEFAULT_ADDONS=1：跳过默认 UBO 扩展下载。addons.mozilla.org 不稳时很有用，否则坏掉的扩展缓存会挡住启动。

匿名遥测默认开着 ​

默认会向官方 Worker 上报脱敏后的崩溃/挂起信息。解决：CAMOFOX_CRASH_REPORT_ENABLED=false，或按 README 自建上报端点。

合法与用途边界 ​

它能绕过不少常见的机器人检测，不代表你可以违规抓站或绕过网站服务条款。只用在自己有权访问的站点，或明确允许自动化的场景。

WANGXXXL 实测于 2026-10-25 ​

  • 环境：Linux 云电脑，Node.js 22.20.0，@askjo/camofox-browser 1.18.1；npm install --omit=dev 后 CAMOFOX_BIND_HOST=127.0.0.1 npm start。
  • 健康检查：GET /health → ok: true，engine: camoufox，browserConnected: true；浏览器预热后 RSS 约 243 MB。
  • 文档：/openapi.json 返回 OpenAPI 3.0.3，info.version 为 1.18.1；/docs 可打开。
  • 导航 + 快照：POST /tabs 打开 https://example.com，返回 httpStatus: 200、navigationOk: true；GET .../snapshot 得到约 1052 字符的无障碍树文本，含可点击引用 [e1]（Learn more → iana.org），refsCount: 1，truncated: false。
  • 未测：Cookie 导入、代理/GeoIP、Docker 部署、对抗真实 Cloudflare 挑战页的成功率（本页不编造成功率）。
